# v0.7.3 — Verified performance optimization plan

Status: baseline audited on 2026-11-03 against v0.7.2 commit
`a89baf70bba9c5695719c7152f64bd8954901de6`; optimizations are not implemented.
See [audit evidence and reproduction](0.7.3-audit.md). Measurements are specific
to the documented fixtures and machine, not universal performance guarantees.

Scope: reduce search snapshot memory, serialization churn, and warm overlay
allocations. Tab geometry and layer changes are maintenance work without a
measured performance benefit. Preserve the 12-byte Cell, platform parity,
snapshot correctness, and short grid lock holds.

Implement separately on project-approved branches. Start with a regression test
or benchmark; request approval for public API changes and broader refactors.

## 1. P1 — Compact the search snapshot without losing cell coordinates

Locations: `src/terminal/grid/selection.rs` (`Grid::search_text`),
`src/terminal/search.rs` (`SearchText::find`), `src/app/search_ui.rs` (`refresh_search`).

Confirmed: every compiled query builds a snapshot while holding the grid mutex;
regex matching then runs outside the mutex. On a 160-column grid with 5,000
history rows and 24 screen rows, the dense fixture retains 808,704 column tuples.
Their capacity is 1,048,576 tuples: **25,165,824 bytes (24 MiB)**, rather than the
original plan's estimated 19.2 MB. Sparse 20-character rows retain **3 MiB** of
column capacity. Both still traverse every cell. See the audit for timings and
allocation traffic, which differ from retained capacity.

A snapshot containing only text and row starts is insufficient. The audit
produces identical text and row starts in two 4-column grids, but a heart+VS16
match occupies one versus two cells. Stored widths depend on terminal state and
history; Unicode width recomputation cannot recover them reliably.

- [ ] Design a compact immutable mapping that preserves actual stored cell
      boundaries and widths. Consider compact entries or sparse exceptions for
      clusters/nontrivial cells; do not mandate text+rows alone.
- [ ] Keep coordinate conversion outside the grid lock and tied to the same
      snapshot. Do not resolve against a later live grid without validation.
- [ ] Reuse bounded text/mapping buffers in `SearchBar` where practical; release
      or cap oversized retained buffers when closing search/changing panes.
- [ ] Preserve exact selections for wide characters, partial-cluster matches,
      combining marks, shell line-editor widths, resize history, soft wraps,
      trimmed hard lines/newline matches, alternate screen, and empty input.
- [ ] Benchmark dense and sparse snapshots, zero matches, and the 10,000-match
      cap. Measure lock duration and total query time separately, including
      coordinate conversion and buffer retention after closing the overlay.

Acceptance: reduce measured snapshot memory and lock duration without changing
results or degrading capped-match query latency. **A >10x lock reduction is an
experimental target, not a verified result or a prerequisite justified by this
audit.** Report actual before/after numbers on identical fixtures.

## 2. P2 — Avoid serialization solely to calculate byte budgets

Locations: `src/ai/json.rs`, `src/ai/mod.rs` (`compact`), `src/ai/http.rs` (`quote`).

Confirmed: `compact()` serializes all history to count bytes and serializes the
selected prefix again while choosing the compaction boundary. Serialization
when building the summarization prompt is necessary output, not a third
length-only pass. `Json::encode` also allocates recursively for object keys,
values, collections, and formatting.

Measured: one length-counting pass over 100 two-field messages with 5,000-byte
ASCII content produces 502,800 encoded bytes, **3,100 allocation/reallocation
calls**, and **4,165,300 requested bytes**. For a 500,000-byte ASCII input,
`quote()` makes **7 calls / 3,500,007 requested bytes**; the documented
escape-heavy input makes **11 calls / 10,500,007 bytes**. These are allocation
traffic, not peak resident memory. Four `.replace()` calls are not the complete
allocation count because growth and outer formatting also allocate.

- [ ] Add allocation-free encoded-length calculation, or a counting sink shared
      with the serializer; use it in both budget-counting passes.
- [ ] Assert length equals `encode().len()` for every JSON variant, nested
      arrays/objects, escaped keys, all control characters, UTF-8, and numbers.
      Preserve current compaction boundary selection and threshold behavior.
- [ ] Replace curl-config quoting with one escape writer; preserve surrounding
      quotes and the existing backslash, quote, LF, and CR semantics.
- [ ] Preserve transport safety: credentials/bodies remain on stdin, `data-raw`
      must not interpret a leading `@` as a local file, and cancellation,
      timeout and error handling remain intact. Direct streaming is optional
      and requires transport tests, not just string equality tests.
- [ ] Measure length-only allocation count and quote allocation traffic before
      and after, with ASCII and escape-heavy fixtures.

Acceptance: zero allocations for byte-budget calculation; equivalent JSON
lengths and compaction decisions; no intermediate full-size replacement
strings in quoting. Do not claim the whole compaction/request path is allocation-free.

## 3. P2 — Replace stem gamma arithmetic with lookup tables

Location: `src/render/atlas/raster.rs` (`stem_boost`).

Confirmed: two fixed gamma values (0.78 / 0.55), 256 inputs each; current code
calls `powf` only for values 1..254. The audit checks all **512 outputs** and
compares the current function with a precomputed-table lookup. See the audit
for microbenchmark timings. This establishes a local arithmetic opportunity,
not an equivalent whole-frame or glyph-rasterization speedup; cached glyphs
and CoreText paths may not execute this function.

- [ ] Generate and check in two 256-byte tables from the existing **f32** formula
      and rounding expression, with a reproducible generation method.
- [ ] Preserve runtime `THICKEN` selection. No new dependency is needed.
- [ ] Verify every byte against the original expression on macOS and Linux,
      including exact endpoints 0 and 255.
- [ ] Benchmark the lookup and actual fontdue rasterization separately, using
      uncached glyphs and documenting which font/backend executes the function.

Acceptance: equivalent output, 512 bytes of table data, no runtime `powf` in
`stem_boost`. Whole-rasterization improvement remains to be measured.

## 4. P2 — Remove all identified warm-overlay allocations

Locations: `src/render/renderer/ui/{tab_bar,search_box,history_popup}.rs`,
`src/render/renderer/pane_row.rs`.

Confirmed using actual builders and a real Metal atlas after three warmups:
**5 allocation/reallocation calls** for the two-tab fixture, **3** for search,
and **47** for history. These are per builder invocation, not every application
frame; actual redraw frequency depends on invalidation.

The original checklist missed search query collection, owned error/status
labels, history query/result collections, and history badge/counter formatting.

- [ ] Tab bar: replace collected character buffers while preserving prefix
      stripping, centering, Unicode character truncation, and the final `…`.
- [ ] Search box: use borrowed static status labels and stack-formatted counts;
      eliminate the query `Vec<char>` while preserving width-aware tail display,
      ellipsis, cursor position, invalid-regex status, and the 10,000+ count.
- [ ] History popup: remove allocations from sort badge, counter, query and
      result text, as well as preview wrapping. Borrow UTF-8 slices at character
      boundaries, preserve empty lines and highlight indices, and stop preview
      work after the visible rows instead of materializing the whole command.
- [ ] Arabic clusters: size scratch storage for `MAX_CLUSTER_BYTES` plus the
      maximum UTF-8 replacement growth; do not hardcode 64 bytes. A real
      64-byte cluster (`ب` plus 31 fatha marks) becomes **65 bytes** after the
      joined presentation-form substitution. Preserve every mark.
- [ ] Add allocation assertions for warm redraws and output/layout regression
      tests across empty, long, UTF-8, error, truncation, and maximum-size cases.

Acceptance: zero calling-thread allocations in the specified overlay builders
with warmed glyph/cache and instance storage; zero temporary cluster allocation
for joined Arabic text. Cold glyph rasterization/cache growth is measured
separately. Verify the real UI on both platforms; the baseline builder probe is
not a full end-to-end interaction or pixel-equivalence test.

## 5. P3 — Share tab geometry while preserving behavior

Locations: `src/render/renderer/ui/tab_bar.rs`, `src/render/renderer/mod.rs`.

Confirmed: start/end span formulas and the close-button visibility threshold
are duplicated. An independent arithmetic sweep of 10,084,181 cases found no
span-containment mismatch in the 9,734,423 cases where tab count does not exceed
available columns. No general click-misalignment regression is established.

- [ ] Extract an internal pure geometry helper used by rendering and hit tests.
- [ ] Preserve the one-cell close glyph at `c0+1` and its intentionally larger
      three-column click target `c0..=c0+2`.
- [ ] Test span thresholds 4/6/10, non-divisible widths, badge cutoff at index 9,
      empty/one-tab inputs, and the reserved New Tab region.
- [ ] Treat the synthetic case of more tabs than available columns separately:
      the current inverse calculation can select a zero-width span. Reproduce
      through the UI and agree on behavior before turning extraction into a fix.

Acceptance: one source of span geometry with unchanged observable behavior.
No performance gain is claimed.

## 6. P3 — Remove the render-to-split layering exception

Locations: `src/split.rs`, `src/render/renderer/{mod,frame,pane_row}.rs`,
`src/layering_tests.rs`.

Confirmed: exactly five tolerated dependency pairs exist: platform→config,
platform→keymap, platform→AppEvent, render→split, and render→platform.

- [ ] Move `PaneRect` to a render-owned location, updating its producers and
      consumers; keep layout behavior unchanged and validate split tests.
- [ ] Remove only the now-unneeded `render → split` tolerance and run the layer
      test. Expected exception count: **5 → 4**.

Platform-owned `WindowLook`, resolved keycodes/callbacks, and Metal drawable
setup decoupling are separate follow-ups, not implicit work in this item.
Acceptance: unchanged pane layout and fewer tolerated dependencies. No measured
runtime performance benefit is claimed.

## Verification and completion

For implementation, run the project checks:

```sh
cargo check
cargo check --target x86_64-unknown-linux-gnu
cargo test # outside the sandbox: PTY tests require openpty
cargo clippy --all-targets -- -D warnings
git diff --check
cargo run --release -- +bench-ram
cargo run --release -- +bench-perf
```

`+bench-perf` already runs latency, **20,000-line stress**, and feature
benchmarks via `main.rs`; a separate `+bench-stress` invocation is optional.
Inspect benchmark verdicts, not just process exit status. RAM budgets include
85 MB (1 window/1 tab), 95 MB (1 window/3 tabs), 145 MB (2 windows/6 tabs), and
10 MB cleanup delta. Footprint varied by more than 25 MB between two runs of
the same commit (see the audit), so compare before/after using ranges from
repeated `+bench-ram` runs, never one run against one run. The intended PTY limits distinguish average ≤1 ms from
P99 ≤3 ms, but the current benchmark labels a same-process pipe measurement as
PTY latency. Add a real PTY/shell output-completion measurement before claiming
that SLA; the existing passing verdict does not verify it.
The stress benchmark's ≥20,000 lines/s measures parser/grid ingestion, not
full GPU presentation throughput. Its chunk timings are not actual frame times.

Add targeted allocation/performance tests above; the existing suite alone does
not establish zero overlay allocations or a faster search snapshot. Verify UI
flows and cross-platform results before calling an implementation complete.
Update `ROADMAP.md` when an item is completed/descoped and `README.md` when
user-visible behavior changes. Commit only when requested.
