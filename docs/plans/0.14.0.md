### Linux implementation follow-ups

- [x] **Linux `rasterize_color` negative `pitch` parity & checked size.**
  FreeType keeps `bmp.buffer` at the lowest address (`y * abs(pitch)` never
  reads OOB, confirmed against `libfreetype.dylib`), so only a vertical flip
  is possible if `"Noto Color Emoji"` ever returns `pitch < 0`; align row
  reversal with `blit_ft_bitmap` and add `checked_mul` guards. Low severity.
  See [verified findings plan](./2026-11-13-verified-findings-fixes.md) (Task 2).
  Done 2026-11-16 on `fix/linux-deferred-items`: `bgra_to_straight_rgba`
  reverses rows for `pitch < 0`, checks every size product and rejects a
  pitch narrower than a row or a short buffer. Five unit tests; the negative
  pitch one failed (flipped rows) before the fix. No live strike with
  `pitch < 0` was found, so this is parity hardening, not an observed bug.

- [x] **Linux Kitty `t=s` `/dev/shm` truncation check (`SIGBUS`).**
  macOS rejects concurrent `ftruncate` (`EINVAL`) and fails on `MAP_PRIVATE`,
  so keep `MAP_SHARED` on macOS. Check on a real Linux host whether same-UID
  `/dev/shm` truncation triggers `SIGBUS` and whether Linux can read `shm_open`
  fds via `read_range` instead of `mmap`. Low severity (same-UID only).
  See [verified findings plan](./2026-11-13-verified-findings-fixes.md) (Task 3).
  Confirmed and fixed 2026-11-16 on Ubuntu (kernel 7.0, GNOME Wayland): a C
  probe truncating after `fstat` died with `SIGBUS` under both `MAP_SHARED`
  and `MAP_PRIVATE`, while `pread` on the same fd returned short without a
  signal. Linux now reads (`read_shm_bytes`, seek + bounded read); macOS keeps
  `MAP_SHARED`. Regression test
  `kitty_shared_memory_truncated_after_fstat_reads_short` dies with `SIGBUS` on
  the old mmap path and passes with the read path.
