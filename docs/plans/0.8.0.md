# v0.8.0 — Release plan and record

Status: released as v0.8.0 on 2026-11-04. It ships the unreleased [v0.7.3](./0.7.3.md)
and [v0.7.4](./0.7.4.md) items (release notes: <https://github.com/Matrix-I/litty-terminal/releases/tag/v0.8.0>,
published on GitHub). The checklist below is the follow-ups migrated from ROADMAP.md; none was
completed by this release, and states and evidence are preserved.

## Open follow-ups (not completed in v0.8.0)

Carried over from v0.7.0 and v0.7.1 release validation; none of these block a release and each is listed under **Known limitations** in its release notes. The [structural refactor](./0.7.1.md#structural-refactor-4-phases-zero-behavior-change-shipped-in-v071) shipped in v0.7.1; its outstanding follow-ups below are candidates for the next release.

- [ ] Linux runtime run of `scripts/linux/test.sh` on a machine with enough RAM (or a bigger podman VM) for the v0.7.1 layered layout; v0.7.1 only compile- and clippy-checked the Linux twins
- [ ] Linux desktop checks: Kitty lock modifiers, Quick Terminal (X11 and Wayland), real `xdg-open` dispatch, fish on real Linux
- [ ] Live-provider smoke tests for OpenAI, OpenRouter and other non-Anthropic providers; Nushell older than 0.116.1
- [ ] Measure per-session memory after `yo` usage
- [ ] **Investigate flaky `Memory Leak <= 10 MB` check in `scripts/pre-release-check.sh`** (seen once, 2026-11-01)
  - Evidence of the failure: macOS arm64, code at `865f4a0` with the v0.7.0 version bump uncommitted (`5f24865` carries only version/docs changes). Step 4/4 "After Closed & Freed" reported RSS 120.69 MB, footprint **100 MB**, leak delta **+20 MB** (limit 10 MB). Same run: 1w/1t 80 MB, 1w/3t 80 MB, 2w/6t 88 MB, all within budget. The run immediately followed `cargo check`, Linux check, `clippy` and `cargo test` in the same shell command, so the machine may still have been under load or have had a warm memory state; this is a hypothesis, not established.
  - Evidence it is not deterministic: one run before it passed at `865f4a0`, and three consecutive reruns afterwards all passed with 1w/1t 79 MB and footprint after cleanup **66 MB** (delta -13 MB, reported as 0.00 MB leak). Overall 1 failure in 5 runs. The pass/fail exit code of the failing run was not captured.
  - If it reappears: record the commit, whether the run followed a build or test, and the full "Memory Profile" step lines (RSS and footprint for all four steps) before rerunning. A repeat at +20 MB with a quiet machine would point to a real retained allocation after closing windows (compare against the 41 MB footprint measured with all windows closed on 2026-11-01); a footprint that varies between 66 MB and 100 MB for the same workload suggests allocator or IOSurface release timing and may warrant sampling the footprint several times after cleanup instead of once.
  - Mentioned under "Validation" in the published v0.7.0 release notes as an unexplained single outlier.


## Structural refactor follow-ups

Carried over from the [v0.7.1 refactor](./0.7.1.md#structural-refactor-4-phases-zero-behavior-change-shipped-in-v071).

- [ ] Render loop: remove per-frame heap allocations found during phase 3 — tab bar `Vec<char>` per title (`ui/tab_bar.rs`), find box status `format!` / `to_string` and query `Vec<char>` (`ui/search_box.rs`), history popup `format!` badges, per-item `Vec<char>` and `preview_lines: Vec<String>` (`ui/history_popup.rs`), inspector title `format!` (`ui/inspector.rs`), hovered-URL `format!` / `clone` (`ui/link_preview.rs`), Arabic joined-cluster `String` (`pane_row.rs`).
- [ ] Share the tab span math (`c0`, `c1`, close / badge reserve) between `Renderer::hit_test_tab_bar` and `ui::tab_bar::build`.
- [ ] Phase 4: one CoreFoundation / CoreGraphics FFI module shared by `atlas/coretext.rs`, `macos.rs` (`NSRect` / `NSPoint` are layout-identical to `CGRect` / `CGPoint`) and the CoreText benchmark's own extern block in `app/latency_benchmarks.rs`.
- [ ] Remove tolerated `render → split`: move `PaneRect` into `render`.
- [ ] Remove tolerated `render → platform`: let `Renderer::new` expose a post-surface hook for Metal drawable setup.
- [ ] Remove tolerated `platform → config`: pass a platform-owned `WindowLook` to `apply_window_config`.
- [ ] Remove tolerated `platform → keymap` / `AppEvent`: platform takes a resolved key code + modifier mask and a `Send` callback instead of `EventLoopProxy<AppEvent>`.
- [ ] Linux `confirm_close` fallback (`zenity` missing → close) differs from `platform::confirm` (missing → cancel); unify after deciding the intended behavior.
- [ ] `platform::prepare_window_attributes` for the `WindowAttributesExtMacOS` block in `app::window::create_window`.
- [ ] Linux behavior gaps behind explicit no-ops: `caps_lock` (Kitty never reports Caps Lock), `system_dark` (no appearance detection; e.g. xdg-desktop-portal `color-scheme`), `beep`, update progress dialog.
- [ ] Linux has no `wcwidth` override for spacing marks (`grid` uses `macos_wcwidth` only on macOS); check glibc `wcwidth` vs unicode-width for Indic scripts.
- [ ] `render/atlas/coretext.rs` exports `macos_coretext_rasterize`, which `render/atlas/linux.rs` has no twin for.
- [ ] Optional: lib target (see Task 9 of the phase 4 plan).
