# v0.8.0 — Release plan and record

Status: released as v0.8.0 on 2026-11-04. It ships the unreleased [v0.7.3](./0.7.3.md)
and [v0.7.4](./0.7.4.md) items (release notes: <https://github.com/Matrix-I/litty-terminal/releases/tag/v0.8.0>,
published on GitHub). The checklist below is the follow-ups migrated from ROADMAP.md; the original release evidence is preserved, with the Linux status updated below.

## Post-release packaging addition (2026-11-04)

Added `litty_0.8.0_amd64.deb` around the unchanged published Linux executable,
with an applications-menu launcher and Litty icon. See the
[Debian package verification](../validation/debian-package-0.8.0.md) for packaging,
APT installation/removal evidence and the emulated Vulkan GUI validation limit.

Also added `litty-0.8.0-1.x86_64.rpm` with the same executable, launcher and icon.
See the [RPM package verification](../validation/rpm-package-0.8.0.md) for the
Fedora build/install checks and the scope of launcher validation.

Release downloads retain only installers, the builds required by the updater,
and the signed checksum manifest. Verification reports are linked from the repo;
the duplicate Linux `.tar.gz` is no longer published.

- [x] **Investigate flaky `Memory Leak <= 10 MB` check in `scripts/pre-release-check.sh`** (seen once, 2026-11-01)
  - Closed as not reproduced (2026-11-12): 20 of 20 `+bench-ram` runs passed at `a307298` with a busy machine (load 10–26), deltas 0–7 MB. Footprint after cleanup moves between 34 and 64 MB in steps of about 15 MB, and the check compares that one sample against one baseline sample, so a step can show up as a delta. Reopen with the evidence listed below if it fails again. See the [close-out report](../validation/2026-11-12-macos-closeout.md).
  - Evidence of the failure: macOS arm64, code at `865f4a0` with the v0.7.0 version bump uncommitted (`5f24865` carries only version/docs changes). Step 4/4 "After Closed & Freed" reported RSS 120.69 MB, footprint **100 MB**, leak delta **+20 MB** (limit 10 MB). Same run: 1w/1t 80 MB, 1w/3t 80 MB, 2w/6t 88 MB, all within budget. The run immediately followed `cargo check`, Linux check, `clippy` and `cargo test` in the same shell command, so the machine may still have been under load or have had a warm memory state; this is a hypothesis, not established.
  - Evidence it is not deterministic: one run before it passed at `865f4a0`, and three consecutive reruns afterwards all passed with 1w/1t 79 MB and footprint after cleanup **66 MB** (delta -13 MB, reported as 0.00 MB leak). Overall 1 failure in 5 runs. The pass/fail exit code of the failing run was not captured.
  - If it reappears: record the commit, whether the run followed a build or test, and the full "Memory Profile" step lines (RSS and footprint for all four steps) before rerunning. A repeat at +20 MB with a quiet machine would point to a real retained allocation after closing windows (compare against the 41 MB footprint measured with all windows closed on 2026-11-01); a footprint that varies between 66 MB and 100 MB for the same workload suggests allocator or IOSurface release timing and may warrant sampling the footprint several times after cleanup instead of once.
  - Mentioned under "Validation" in the published v0.7.0 release notes as an unexplained single outlier.


## Structural refactor follow-ups

Carried over from the [v0.7.1 refactor](./0.7.1.md#structural-refactor-4-phases-zero-behavior-change-shipped-in-v071).

- [x] Render loop: remove per-frame heap allocations found during phase 3 — tab bar `Vec<char>` per title (`ui/tab_bar.rs`), find box status `format!` / `to_string` and query `Vec<char>` (`ui/search_box.rs`), history popup `format!` badges, per-item `Vec<char>` and `preview_lines: Vec<String>` (`ui/history_popup.rs`), inspector title `format!` (`ui/inspector.rs`), hovered-URL `format!` / `clone` (`ui/link_preview.rs`), Arabic joined-cluster `String` (`pane_row.rs`).
  - Done in `fd56b0c` (2026-11-03): warm overlay redraws build without heap allocation (`warm_overlay_builders_do_not_allocate`); Arabic clusters use a stack buffer (`joined_maximum_cluster_keeps_every_mark_without_allocating`). `ui/inspector.rs` and `ui/link_preview.rs` no longer contain `format!`, `to_string` or `clone`.
- [x] Share the tab span math (`c0`, `c1`, close / badge reserve) between `Renderer::hit_test_tab_bar` and `ui::tab_bar::build`.
  - Done in `fd56b0c` (2026-11-03): drawing and hit testing share the tab span and close-button geometry (`span`, `slot_at` in `render/renderer/ui/tab_bar.rs`).
- [x] Phase 4: one CoreFoundation / CoreGraphics FFI module shared by `atlas/coretext.rs`, `macos.rs` (`NSRect` / `NSPoint` are layout-identical to `CGRect` / `CGPoint`) and the CoreText benchmark's own extern block in `app/latency_benchmarks.rs`.
  - Done within the render layer (2026-11-12): `src/render/cg.rs` holds `CGPoint`, `CGSize` and `CGRect` for `atlas/coretext.rs` and `backend/metal`. Descoped across layers: `platform/macos/objc.rs` keeps its own `NSRect` / `NSPoint`, since `platform` may not use `render` (and `render → platform` is the edge to remove). The benchmark's extern block stays: it measures the old uncached `CTFontCreateWithName` path on purpose.
- [x] Remove tolerated `render → split`: move `PaneRect` into `render`.
  - Done in `fd56b0c` (2026-11-03): `PaneRect` lives in `render/mod.rs` and the pair is gone from `TOLERATED` in `src/layering_tests.rs`.
- [ ] Remove tolerated `render → platform`: let `Renderer::new` expose a post-surface hook for Metal drawable setup.
- [x] Remove tolerated `platform → config`: pass a platform-owned `WindowLook` to `apply_window_config`.
- [x] Remove tolerated `platform → keymap` / `AppEvent`: platform takes a resolved key code + modifier mask and a `Send` callback instead of `EventLoopProxy<AppEvent>`.
  - Both done in `a5f8cfb` (2026-11-03, [v0.7.4](./0.7.4.md) item 2.7): `platform/types.rs` owns `WindowLook`, `Hotkey`, `MenuCommand` and `PlatformEvent` delivered through an `EventSink`; only `render → platform` remains in `TOLERATED`. Menu selection, Dock reopen, appearance change and the global hotkey were not exercised in a running app at that commit; the user checked them in the macOS smoke test on 2026-11-12.
- [x] Descoped after user-confirmed stable Linux feature testing (2026-11-04); no longer tracked as technical debt: Linux `confirm_close` fallback (`zenity` missing → close) differs from `platform::confirm` (missing → cancel); unify after deciding the intended behavior.
- [x] Descoped (2026-11-12): `platform::prepare_window_attributes` for the `WindowAttributesExtMacOS` block in `app::window::create_window`. The block went away with `winit` in `62b2672` (2026-11-07); native AppKit windowing has no such attributes.
