# v0.13.0 — Planned

Status: planned. Collects every open item carried over by earlier release
records and `ROADMAP.md` (as of v0.12.0, 2026-11-13) so they are resolved in
one release. Each item links to the record that holds its evidence. An item
is closed by a fix with its verification, or by an explicit descope with the
reason.

## Linux

- [ ] **Occlusion events.** No Linux emitter for `WindowEvent::Occluded`, so
  covered or minimized windows keep rendering on PTY output (macOS fixed in
  `dc766fa`). X11: `UnmapNotify`/`MapNotify`, `_NET_WM_STATE_HIDDEN`, and
  `VisibilityNotify` (`FullyObscured`; compositors usually report
  `Unobscured`, so this part needs a real desktop check). Source:
  [perf review finding 2](../validation/2026-11-11-perf-review.md).
- [ ] **Wayland window backend.** `NativeWindow::create` is X11 only; the
  Wayland surface and clipboard paths are unreachable, and IME under GNOME on
  Wayland needs a hand-started `ibus-x11` until text-input is supported.
  Source: [2026-11-11 review](../reviews/2026-11-11-linux-history-ai-graphics.md).
- [ ] **Custom shaders** (GLSL to SPIR-V, offscreen targets). Today the key is
  rejected with one warning per process. Source: same review.
- [ ] **Center new windows** on the focused monitor, as macOS does since
  `eadfda8`. Source: [v0.11.1](./0.11.1.md#carried-over).
- [ ] **Dead keys and Compose sent with `XSendEvent`** no longer compose since
  the keycode-0 hardening in `13073b6`; hardware keys and XTEST are
  unaffected. Decide whether synthetic input must be supported. Source:
  `ROADMAP.md` (Linux IME item).
- [ ] **Legacy `WM_NAME`** stays Latin-1 and garbles non-ASCII titles for
  window managers that ignore EWMH. Decide: fix or descope.
- [ ] **Vulkan failure paths** have no fault-injection tests (creation,
  submit and present results, `648f717`, `7d1e1f4`).

## Graphics

- [x] Kitty `a=d`: alternate-screen scoping of deletions against the grid
  caller. Done 2026-11-13: the grid passes the active screen; deletions
  touch only that screen's placements, and `A`/`I` free only image data no
  remaining placement shows (Kitty keeps one store per screen; refined by
  the follow-ups below). Test:
  `kitty_delete_on_alt_screen_keeps_main_screen_images`.
- [x] Follow-ups found in review (2026-11-13), all older than the scoping
  fix, done the same day: images remember the screen that transmitted them
  and `A`/`I` free only that screen's unused images; `d=I` with `p=`
  removes only that placement (as `i` does) and frees the data once
  nothing shows it; `Store::place` and `place_virtual` replace a same-id
  placement only on the same screen; leaving the alternate screen frees
  the images it transmitted that the main screen does not show.
  Image ids stay shared: placing an image transmitted on the other screen
  still works (Kitty would answer `ENOENT`), and re-transmitting an id
  moves the image to the sending screen, so a main-screen `d=I` then
  leaves it to eviction. `virtual_for` does not filter by screen. Source: `ROADMAP.md` (graphics follow-ups, 2026-11-12).

## Performance

- [x] **T5 leftover**: emoji cluster interning (SipHash kept on purpose).
  Done 2026-11-13: a 32-entry memo of recent appends (cell value + char →
  cluster id), checked against the table on use, skips building and hashing
  the text for repeated sequences. Fixed size, so no flooding surface.
  `perf_probe emoji_clusters`, release, interleaved builds (2 clean rounds;
  2 rounds disturbed by load dropped): 12.12 / 12.24 → 11.21 / 11.40 ns/B
  (~7%); `unicode_mixed` unchanged (4.06–4.13).
  Source: [v0.11.0](./0.11.0.md#carried-over).

## Deferred

- **T1** (shaping/rasterization under the grid lock). Descoped on
  2026-11-13: after T2 the render holds the lock 1–3% of the time
  (measured 2026-11-09), so a row snapshot would win at most ~3%
  throughput for a large refactor of `build_pane_row`. Revisit if a
  cache-miss-heavy workload shows the hold above ~10%. Source:
  [performance gaps](./2026-11-08-performance-gaps.md#t1-move-shaping-and-rasterization-out-of-the-grid-lock).
- **Optional lib target** (Task 9 of the
  [phase 4 plan](./2026-11-01-layered-layout.md)). Descoped on 2026-11-13:
  no consumer needs crate internals (`tests/` runs the binary and real
  shells; no `benches/`), and a lib weakens `dead_code` checks. Revisit
  when a test or benchmark needs `Grid` or other internals.

- **LLM assistant validation** (live smoke tests for non-Anthropic
  providers, Nushell older than 0.116.1, per-session memory after `yo`).
  Descoped from v0.13.0 on 2026-11-13: the assistant is nice to have and
  these are release validation, not missing features. Planned again only
  if an issue is opened against them. Source: `ROADMAP.md` (LLM assistant
  item), [v0.8.0](./0.8.0.md#open-follow-ups-not-completed-in-v080).
