# v0.10.0 — Bare-Metal GPU, Native Windowing, and SIMD Core Plan

Status: planned (post-[v0.9.0](./0.9.0.md)).

## Release scope (v0.10.0)

v0.10.0 ships the work on `main` up to the release commit; this section records
what that covers against the plan below. Release validation:
[release-0.10.0](../validation/release-0.10.0.md).

Shipped:
- Phase 1 — SIMD VT/search core, stack bitsets and `madvise` (`350d415`),
  `regex` replaced by `regex_lite` (`d0dad3c`, `c2e6d6a`, `34531d7`).
- Phase 2 — native CoreText/FreeType, ImageIO and zero-allocation overlays
  (`b9db7e4`, `04fcebb`).
- Phase 3 — direct Metal and Vulkan backends, `wgpu` removed (`203ea10`,
  `b40ed09`, `47fa8c8`, `41c7d47`).
- Phase 4 — native AppKit (macOS) and single-`epoll` X11 (Linux) windowing,
  `winit` removed (`88c8daa`, `eb7da4f`, `62b2672`, plus the follow-up input
  and window fixes); `x11rb` removed with the Quick Terminal (`cd1d0da`).

Quantitative targets (§1) not reached in this release (macOS arm64 Retina,
release build, measured for the release):

| Metric | Target | Measured |
| :--- | :---: | :---: |
| Idle RAM, 1 window (`footprint`) | < 22 MB | 66 MB |
| Idle RAM, 0 windows (`footprint`) | < 6 MB | 33 MB |
| Release binary size | < 1.2 MB | 2.1 MB (macOS), 2.7 MB (Linux) |

PTY throughput (> 2.5 GB/s) and cold startup to first presented frame (< 8 ms)
were not measured with the method in §1 for this release.

Carried over to the next release:
- 4.2 — native Wayland client. Linux ships the X11 backend only; Wayland
  sessions run Litty through XWayland.
- 4.3 — the macOS half of the `winit` removal benchmark (TODO list below).
- The quantitative targets above.

Scope: eliminate heavy third-party runtime abstractions (`wgpu`, `winit`, `fontdue`, `rustybuzz`, `regex`, `png`, `miniz_oxide`, `smithay-clipboard`, `x11rb`) in favor of direct OS/GPU APIs (Metal, Vulkan/EGL, AppKit, Wayland/X11, CoreText, ImageIO, FreeType/HarfBuzz) and hardware SIMD (`NEON` on `aarch64`, `AVX2`/`SSE2` on `x86_64`), driving memory footprint, binary size, and CPU throughput to hardware limits while keeping 100% of the codebase in Rust.

Implement each milestone and sub-item on a dedicated `feat/<topic>` or `perf/<topic>` branch. Preserve the 12-byte `Cell` invariant, platform parity (`src/platform/{macos,linux}/`), short `Grid` lock holds, and zero heap allocation on hot paths. Every behavior change or optimization ships with unit/equivalence tests and before/after benchmark numbers.

## 2. Phase Breakdown

### Phase 1 (Milestone 0): SIMD VT Core & Zero-Waste Grid Memory (`src/terminal/`)

- **Locations**: `src/terminal/grid/mod.rs`, `src/terminal/grid/perform.rs`, `src/terminal/grid/storage.rs`, `src/terminal/search.rs`
- **Dependencies removed**: `regex`

#### 1.1 Architecture-Specific SIMD ASCII Scanner & Bulk Cell Splat (`src/terminal/grid/simd.rs`)
- Replace the scalar `printable_ascii_prefix` fold in `src/terminal/grid/mod.rs:907-920` with explicit architecture intrinsics:
  - `aarch64` (`std::arch::aarch64`): load 64 bytes per iteration (`vld1q_u8_x4`), range-check `0x20..=0x7E` via `vcgeq_u8` / `vcleq_u8` or unsigned wrap `vsubq_u8(v, 0x20) < 0x5F`, collapse with `vminvq_u8` / `vmaxvq_u8`.
  - `x86_64` (`std::arch::x86_64`): 32-byte `_mm256_loadu_si256` range checks with `_mm256_movemask_epi8` and ` trailing_zeros()`.
- Vectorize the contiguous `Cell` write path when `!self.modes.insert_mode && !self.cur.line_drawing`: widen `u8` ASCII bytes into 32-bit `codepoint` lanes and interleave with precomputed `(fg, bg)` pairs directly into the destination row slice `&mut [Cell]`.
- Verify bit-for-bit state equivalence across arbitrary chunk boundaries via `src/terminal/grid/ascii_run_tests.rs`.

#### 1.2 Inline Control & CSI SGR Fast-Path (Bypassing `vte::Parser`)
- Real-world terminal output (`cargo build`, `rg`, `git log`, `ls --color`) alternates short printable runs with `\r\n`, `\n`, and `\x1b[...m` SGR sequences.
- In `Grid::feed_bytes` (when `self.ground && self.apc_state == 0 && self.osc_len.is_none() && self.dcs.is_none()`):
  - Handle `\r`, `\n`, and `\r\n` transitions inline immediately after an ASCII run without yielding to `vte::Parser::advance`.
  - Detect `\x1b[` followed by digits/semicolons and terminated by `m` (`\x1b[0m`, `\x1b[1;31m`, `\x1b[38;2;R;G;Bm`), parse integer parameters in-place on a stack array, apply `self.sgr(...)`, and continue scanning the buffer in the same loop iteration.

#### 1.3 Scrollback Physical Page Reclamation (`madvise`) & Bitset Compaction
- In `src/terminal/grid/storage.rs` and `src/terminal/grid/mod.rs`:
  - When scrollback is cleared (`Cmd+K` / `Ctrl+Shift+K`, `CSI 3 J`, or `full_reset`), issue `libc::madvise(ptr, byte_len, libc::MADV_FREE)` on macOS and `libc::MADV_DONTNEED` on Linux over the page-aligned region of `Grid::cells` outside the active screen rows. This immediately returns committed dirty pages to the OS kernel without reallocating the ring buffer.
  - When leaving the alternate screen (`set_alt(false, _)`), drop `self.alt` backing capacity (`Vec::new()` already drops, verify no retained excess capacity in `dcs_buf`, `apc_buf`, `response`).
  - Pack per-row/per-column boolean vectors (`dirty: Vec<bool>`, `tab_stops: Vec<bool>`) into compact `u64` bitsets (`[u64; 4]` covers up to 256 rows/cols in 32 stack bytes with zero heap allocation and single-instruction `dirty != 0` / `trailing_zeros()` dirty-row iteration).

#### 1.4 SIMD Smart-Case Search & Lightweight Thompson NFA (`src/terminal/search.rs`)
- Replace the `regex` crate dependency with:
  - A SIMD accelerated two-way / `memchr` substring matcher for literal and case-insensitive smart-case queries (covers >95% of interactive searches with zero heap DFA allocation).
  - A compact, bounded Thompson NFA engine (~300 LOC in `src/terminal/search/regex_lite.rs`) supporting standard character classes, alternations, quantifiers, and anchors for regex mode, bounded to zero dynamic heap growth during matching.

### Phase 2 (Milestone 1): Native Font Shaping, Rasterization & Image Decoding (`src/render/atlas/`, `src/terminal/graphics/`) — Completed

- **Locations**: `src/render/atlas/mod.rs`, `src/render/atlas/coretext.rs`, `src/render/atlas/linux.rs`, `src/render/atlas/shaper.rs`, `src/terminal/graphics/kitty.rs`, `src/terminal/graphics/png.rs`
- **Dependencies removed**: `fontdue`, `rustybuzz`, `memmap2`, `png`, `miniz_oxide`

#### 2.1 macOS: 100% CoreText + ImageIO (`src/render/atlas/coretext.rs`)
- Unify primary glyph rasterization, Nerd Font / fallback lookup, ligature shaping (`CTLineCreateWithAttributedString` + `kCTFontFeatureSettingsAttribute`), and color emoji (`sbix` / `CTFontDrawGlyphs`) under `CoreText` and `CoreGraphics`.
- Because `CTFontRef` shares read-only font tables directly from the macOS WindowServer / kernel shared cache, Litty eliminates both `fontdue`'s parsed heap outline tables and `rustybuzz`'s `Mmap` handles.
- Replace the `png` + `miniz_oxide` crates in Kitty image decoding (`src/terminal/graphics/kitty.rs`) on macOS with `ImageIO.framework` (`CGImageSourceCreateWithData` + `CGImageSourceCreateImageAtIndex`), leveraging Apple's system media decoder.

#### 2.2 Linux: Dynamic System `libfreetype`, `libharfbuzz`, `libfontconfig` (`src/render/atlas/linux.rs`)
- Bind directly to the system shared libraries (`libfontconfig.so.1`, `libfreetype.so.6`, `libharfbuzz.so.0`) that are already mapped into every Linux desktop session.
- Implement a minimal RFC 1950/1951 deflate + PNG chunk reader (~350 LOC) or link system `libz.so.1` for Linux Kitty PNG payloads so `png` and `miniz_oxide` are removed across all targets.

#### 2.3 Zero-Allocation UI Overlay Text Formatting (`src/render/renderer/ui/`)
- Complete the v0.8.0 structural follow-up to remove all per-frame heap allocations in the render loop:
  - Replace `Vec<char>` and `format!` in `ui/tab_bar.rs`, `ui/search_box.rs`, `ui/history_popup.rs`, `ui/inspector.rs`, `ui/link_preview.rs`, and `pane_row.rs` with stack-allocated fixed buffers (`[u8; 128]` / `core::fmt::Write` cursor) and direct UTF-8 iterator slicing.

### Phase 3 (Milestone 2): Direct Metal & Vulkan/EGL GPU Backend (`src/render/`)

- **Locations**: `src/render/renderer/gpu.rs`, `src/render/renderer/frame.rs`, `src/render/renderer/mod.rs`, `src/render/postfx.rs`, `src/render/image_layer.rs`, `src/render/shaders/`
- **Dependencies removed**: `wgpu`, `pollster`

#### 3.1 Minimal Backend Interface (`src/render/backend/mod.rs`)
- Litty's renderer requires only:
  1. Device & swapchain surface lifecycle (`create_surface`, `resize`, `release_swapchain`).
  2. Two textures for the glyph atlas (`R8Unorm` monochrome + `RGBA8Unorm` color emoji) plus on-demand textures for Kitty inline images.
  3. Three pipelines: instanced cells (`vs_main`/`fs_main`), rounded corners (`vs_corner`/`fs_corner`), and image/postfx pass.
  4. One host-visible instance buffer (`12 bytes × cells`), one viewport buffer, and one 208-byte uniform block.

#### 3.2 macOS Direct Metal Backend (`src/render/backend/metal.rs`)
- Use the existing zero-dependency Objective-C runtime layer (`src/platform/macos/objc.rs`) to drive `MTLDevice`, `MTLCommandQueue`, `MTLRenderPipelineState`, `MTLTexture`, and `CAMetalLayer`.
- Translate `src/render/shaders/shader.wgsl` to native Metal Shading Language (`src/render/shaders/shader.metal`).
- **Unified Memory Zero-Copy**:
  - Allocate the per-window `Instance` buffer and `Viewport` buffer with `MTLResourceStorageModeShared`.
  - `Renderer` writes dirty rows directly into the Metal buffer's CPU pointer (`[MTLBuffer contents]`), eliminating the duplicate `Vec<Instance>` on the Rust heap and avoiding `queue.write_buffer` staging copies.
- **Swapchain Footprint Control**:
  - Configure `CAMetalLayer`: `maximumDrawableCount = 2` (saving 8–15 MB of IOSurface memory per Retina window compared to triple buffering), `framebufferOnly = YES`, `allowsNextDrawableTimeout = YES`.
  - When a window is minimized, hidden, or closed, invoke `[CAMetalLayer removeFromSuperlayer]` / drawable pool release so idle background windows consume near-zero GPU surface memory.

#### 3.3 Linux Direct Vulkan / EGL Backend (`src/render/backend/linux_gpu.rs`)
- Load `libvulkan.so.1` dynamically via `dlopen`/`dlsym` (with a lightweight `libEGL.so.1` + `libGLESv2.so.2` fallback for older drivers/VMs without Vulkan).
- Embed precompiled SPIR-V bytecode (`shader.spv`, ~8 KB) in the binary so no shader compiler (`naga` / `shaderc`) is linked at runtime.
- Map `VK_MEMORY_PROPERTY_HOST_VISIBLE_BIT | VK_MEMORY_PROPERTY_HOST_COHERENT_BIT` instance buffers for direct dirty-row writes.
- Use `VK_PRESENT_MODE_FIFO_KHR` with `minImageCount = 2` to minimize swapchain VRAM/RAM on Wayland and X11.

### Phase 4 (Milestone 3): Native Windowing & Unified Kernel Event Loop (`src/platform/`, `src/app/`)

- **Locations**: `src/app/`, `src/platform/macos/`, `src/platform/linux/`
- **Dependencies removed**: `winit`, `smithay-clipboard`, `x11rb`

#### 4.0 Backend-independent window and input API (`src/platform/gui.rs`, `src/platform/input.rs`) — Done
- `keymap`, `app/`, `render/` and `platform/` program against `platform::gui` (`Window`, `WindowId`, dpi, `CursorIcon`, `WindowEvent`, `Ime`, `EventProxy`, `EventHandler`/`LoopCtx`/`Flow`/`WindowSpec`, `run`) and `platform::input` (`Key`, `KeyInput`, `Mods`, ...). `winit` is imported only by `platform/gui.rs` (plus the native-tab extension in `platform/macos/tabs.rs`).
- Native backends now replace `gui.rs` internals only: implement `run`, `LoopCtx::create_window`, the `Window` methods, `RawHandle`, and the `WindowEvent` conversion, then delete `winit`.

#### 4.1 macOS AppKit Native Lifecycle (`src/platform/macos/`)
- Expand `src/platform/macos/` (which already implements native tabs, vibrancy, menus, hotkeys, dialogs, and clipboard via `objc_msgSend`) to own `NSApplication`, `NSApplicationDelegate`, `NSWindow`, `NSWindowDelegate`, and a custom `LittyView : NSView <NSTextInputClient>`.
- Full `NSTextInputClient` implementation (`insertText:replacementRange:`, `setMarkedText:selectedRange:replacementRange:`, `unmarkText`, `firstRectForCharacterRange:actualRange:`) for seamless Vietnamese/CJK IME preedit and candidate positioning.
- Register PTY master file descriptors and the control socket directly with `kqueue` / `CFFileDescriptor` / GCD read sources so terminal output wakes the render pass on the next `CADisplayLink` / run-loop turn with sub-microsecond scheduling latency.

#### 4.2 Linux Single-`epoll` Event Loop (`src/platform/linux/`)
- Drive Wayland (`libwayland-client.so`, `xdg-shell`, `wl_seat`, `wl_data_device_manager` for native clipboard) and X11 (`libX11.so` / `libxcb.so` + `libxkbcommon.so` + XIM) directly from a single `epoll` instance in `src/platform/linux/`.
- Register all PTY master fds, the Wayland/X11 display fd, timerfd (cursor blink / visual bell), and the control socket on the same `epoll` instance:
  - Eliminates cross-thread wakeup channel overhead and background reader threads where possible, or wakes the render loop via a single `eventfd`.

#### 4.3 `winit` removal benchmark (Milestone 3 gate) — Linux done, macOS pending

Question: does replacing `winit` with the native AppKit / X11 backends regress performance? Final verdict waits for the macOS run below.

**Method.** Release builds (`lto = "fat"`, stripped) of the same tree with and without `winit`:
- *winit*: `main` at `c2e6d6a` plus `47fa8c8` (Vulkan render area fix — without it the Linux backend draws a single pixel, so frame numbers are meaningless).
- *native*: `94b748c` (`fix(linux): make the native x11 window usable`).
- Startup is launch → first window mapped (not first presented frame), median of 5. Idle RAM/CPU sampled after 4 s settle, CPU over 10 s (resolution 0.1%). Scroll is `+bench-scroll-fps` (3 scenarios × 2 runs), RAM scaling is `+bench-ram`.

**Linux results** (Ubuntu 26.04.1, GNOME Shell 50.1 Wayland session, Intel UHD 620, both builds on XWayland, `Xft.dpi` 192 → scale 2, window 1936 × 1240 px, 60 Hz, Vulkan, 2026-11-07):

| Metric | winit | native | Δ |
| :--- | :---: | :---: | :---: |
| Binary size (release, stripped) | 4.38 MB | **2.65 MB** | **−40%** |
| Startup to window mapped (median) | 24.7 ms | **9.4 ms** | **−62%** |
| Idle RSS, 1 window | 66.5 MB | **63.3 MB** | −3.3 MB |
| Idle PSS, 1 window | 20.8 MB | **18.8 MB** | −2.1 MB |
| Idle CPU | 0.0 – 0.1% | 0.0 – 0.1% | = |
| `+bench-ram` 1w / 1t | 66.6 MB | **63.2 MB** | −3.4 MB |
| `+bench-ram` 1w / 3t | 67.0 MB | **63.6 MB** | −3.4 MB |
| `+bench-ram` 2w / 6t | 67.9 MB | **64.5 MB** | −3.4 MB |
| `+bench-ram` leak delta after close | +0.96 MB | +0.72 MB | = |
| Scroll submission FPS (all scenarios) | 59.6 – 60.0 | 59.6 – 59.9 | = |
| Scroll frame interval p95 | 17.0 – 17.2 ms | 17.1 – 17.4 ms | = |

Notes:
- Scroll is V-Sync bound at 60 Hz in both builds, so it shows no event-loop cost difference either way; `render_p95` (~17 ms) is mostly swapchain acquire wait.
- `winit` on native Wayland (its default here): idle RSS 64.8 MB / PSS 20.2 MB; startup not measurable with the X11 probe.
- Not measured: keystroke-to-photon latency (no benchmark exists yet).

**Linux verdict:** no regression; startup, binary size and RAM improve, idle CPU and scroll are unchanged.

## 3. Rollout Order & Verification Gate

Each milestone is independently shippable, testable, and benchmarked before proceeding to the next:

1. **Milestone 0 — Phase 1 (SIMD VT + Fast-Path SGR/CRLF + `madvise` + Bitsets + SIMD Search)**
   - Verification: `ascii_run_tests.rs` fuzzing chunks `[1, 2, 3, 5, 7, 16, 31, 33, 64, 8192]`, `search.rs` unit tests, `+bench-latency` throughput comparison (`MB/s` before vs after).
2. **Milestone 1 — Phase 2 (Native CoreText/FreeType + ImageIO + Zero-Alloc UI Overlays)**
   - Verification: glyph/ligature/emoji visual & unit tests, Kitty graphics tests (`src/terminal/graphics/tests.rs`), zero heap allocations during steady-state frame rendering.
3. **Milestone 2 — Phase 3 (Direct Metal & Vulkan/EGL Backend, removing `wgpu`)**
   - Verification: `+bench-ram` footprint across `1w/1t`, `1w/3t`, `2w/6t`, and `0w` after close; binary size check (`ls -lh target/release/litty`).
4. **Milestone 3 — Phase 4 (Native AppKit & Linux `epoll` Windowing, removing `winit`)**
   - Verification: full keymap, IME preedit, native tab drag-and-drop, clipboard, and multi-monitor DPI scaling checks on macOS and Linux.
