## High

### TD-1 Linux: closed windows are never destroyed

- Status: Confirmed.
- Where: `src/platform/linux/native/app.rs` (`WINDOWS`, `register_window`),
  `src/platform/linux/native/x11.rs` (`impl Drop for X11WindowInner`).
- Problem: `register_window` pushes a `NativeWindow` clone into the global
  `WINDOWS` list and nothing ever removes it. That clone keeps the
  `Arc<X11WindowInner>` alive, so `XDestroyWindow` / `XCloseDisplay` never run.
- Impact: a closed window stays mapped on screen, each window leaks one X
  connection (fd + Xlib buffers), and the loop keeps polling dead windows
  every cycle.
- Fix: remove the entry when the app drops its window (or on
  `CloseRequested` + destroy), and deregister its fd from epoll.

### TD-2 Linux X11 backend is missing input features winit had

- Status: Confirmed.
- Where: `src/platform/linux/native/x11.rs` (`poll_events`, `lookup`),
  `src/platform/linux/native/window.rs`.
- Problems:
  - Buttons 4/5/6/7 (X11 wheel) map to `MouseButton::Other`; no
    `WindowEvent::MouseWheel` is produced, so **mouse-wheel scrolling does
    not work**.
  - Text comes from `XLookupString`, which only yields Latin-1, and there is
    no XIM / xkbcommon: non-Latin-1 layouts (Vietnamese, Cyrillic, Greek) and
    input methods (IBus-Bamboo, Fcitx-Unikey, CJK) produce no text.
    `set_ime_allowed` / `set_ime_cursor_area` are no-ops.
  - No native Wayland backend; a Wayland session without XWayland cannot open
    a window. `docs/plans/0.10.0.md` §Linux calls for Wayland + XIM.
  - `set_visible`, `focus_window`, `set_outer_position`, `request_attention`
    only update cached state (Quick Terminal show/hide and placement).
  - Every X11 key event reports `repeat = false`; auto-repeat arrives as
    release/press pairs, which the Kitty keyboard protocol reports as real
    releases.
  - Xlib's default error handlers call `exit()`: any protocol error (e.g.
    `BadWindow` during teardown) terminates the app.
- Fix: map buttons 4–7 to `MouseWheel`; add XIM (or xkbcommon + IBus/Fcitx)
  with UTF-8 lookup (`Xutf8LookupString`); detect repeat via
  `XkbSetDetectableAutoRepeat`; install `XSetErrorHandler` /
  `XSetIOErrorHandler`; schedule the Wayland backend.

### TD-3 Kitty graphics: palette PNGs are rejected

- Status: Confirmed.
- Where: `src/terminal/graphics/png.rs` (`decode_png`, `decode_png_scanlines`).
- Problem: `color_type == 3` returns `EINVAL:bad PNG`. The comment says this
  matches the previous contract, but v0.9.0 used
  `png::Transformations::normalize_to_color8()`, which expands palettes, so
  indexed PNGs used to decode. On Linux the new decoder also rejects 16-bit,
  sub-8-bit and interlaced PNGs (macOS falls back to ImageIO). `tRNS`
  transparency for gray/RGB images is ignored on both platforms.
- Impact: common optimized PNGs (pngquant output, icons, screenshots) no
  longer display via `kitty +kitten icat` and similar tools; behavior differs
  between macOS and Linux.
- Fix: implement `PLTE`/`tRNS` expansion, bit depths 1/2/4/16 and Adam7 in
  the pure-Rust path so both platforms behave the same; add tests for each.

## Medium

### TD-4 SGR fast path drops parameters after the 16th

- Status: Confirmed.
- Where: `src/terminal/grid/simd.rs` (`try_parse_simple_csi`),
  `src/terminal/grid/mod.rs` (`feed_bytes`).
- Problem: the fast path stores at most 16 params and silently discards the
  rest, yet still consumes the whole sequence. The `vte` path keeps up to 32
  (`vte::params::MAX_PARAMS`) and `Grid::sgr` iterates all of them.
- Impact: `\e[1;2;…;7m` with 17+ params loses its trailing attributes, and the
  same bytes render differently depending on whether the fast path is taken.
- Fix: return `None` (fall back to `vte`) when more than 16 params are seen,
  or raise the buffer to 32. Test: a 17-param SGR equals the `vte` result.

### TD-5 Metal: CPU writes instance buffers while the GPU may read them

- Status: Plausible.
- Where: `src/render/backend/metal/resources.rs` (`HostBuffer`),
  `src/render/backend/metal/pass.rs` (`present_and_submit`),
  `src/render/renderer/frame.rs` (`render_panes`).
- Problem: instance/viewport buffers are single `MTLStorageModeShared`
  buffers written in place each frame. Submission does not wait and there is
  no in-flight semaphore, so frame N+1 can overwrite rows the GPU is still
  reading for frame N (`nextDrawable` only bounds drawables, not buffers).
  The Vulkan path waits on a fence before acquire and is not affected.
- Impact: intermittent glitches or tearing on rows that change between frames.
- Fix: a `dispatch_semaphore`/completed-handler gate before writing, or
  per-frame buffers matching `maximumDrawableCount`.

### TD-6 macOS: wake-ups from PTY threads may leak autoreleased NSEvents

- Status: Plausible (not measured).
- Where: `src/platform/macos/native/app.rs` (`wakeup_main_loop`), called via
  `EventProxy::send_event` from PTY reader threads.
- Problem: `otherEventWithType:…` returns an autoreleased object, created on a
  background thread with no autorelease pool. Such objects are only freed
  when the thread exits, and PTY reader threads live as long as the pane.
- Impact: memory grows with output volume (one event per coalesced wake-up),
  against the < 50 MB idle budget.
- Fix: wrap the call in `objc_autoreleasePoolPush`/`Pop`; measure with
  `footprint` under sustained output before and after.

## Low

### TD-7 macOS scroll phase is always `Moved`

- Where: `src/platform/macos/native/events.rs` (NSScrollWheel case).
- `on_mouse_wheel` resets `wheel_scroll` only on `Started`/`Cancelled`, which
  no longer arrive, so a fractional remainder carries into the next gesture.
  Fix: map `phase` / `momentumPhase` to `TouchPhase`.

### TD-8 `unicode-width` downgraded from 0.2 to 0.1

- Where: `Cargo.toml` (commit `3edd59e`).
- Width tables differ in edge cases between the two lines; existing width
  tests pass. Record why 0.1 was chosen, or return to 0.2.

### TD-9 `regex_lite` case-insensitive search is ASCII-only

- Where: `src/terminal/regex_lite.rs` at `3617867`.
- `regex` folded Unicode case; searching "Đà" no longer matches "đà".
  Being addressed on `fix/regex-lite-semantics-perf`; verify there.

### TD-10 Linux event loop allocates every cycle

- Where: `src/platform/linux/native/app.rs` (`WINDOWS.lock().clone()`,
  `drain(..).collect()`, `poll_events` returning a `Vec`).
- Minor against the "no allocation on hot paths" invariant; reuse buffers
  like the macOS `deliver_pending_events` does.
