Status: planned; no source fixes implemented. Review date: 2026-11-02.

Scope: runtime-confirmed issues, security/CWE vulnerabilities, crash vectors,
and platform bugs prioritized for resolution in v0.7.2.

## 1. P2 — Full grapheme table repeatedly scans history (CWE-407)

Location: `src/terminal/grid/clusters.rs`, `intern_cluster` and `gc_clusters`.

When all 65,536 entries remain live, each new cluster triggers a collection
that cannot free a slot. Collection scans grid/history while the parser holds
the grid mutex. An isolated optimized harness using the source modules measured
1,000 clusters at approximately 156 ms with a full table versus 0.21 ms with a
fresh table (approximately 740x slower). The harness used `Grid::new(80, 24)`,
fed 65,536 distinct combining-mark clusters through `Grid::feed_byte`, then timed
1,000 further clusters against a fresh grid. It was compiled with `rustc -O`
on macOS. These are local reproduction measurements, not CI thresholds; UI
latency in a running Litty window was not measured.

- [x] Add a regression that fills the table with live clusters, then proves
  repeated misses do not repeatedly scan the entire grid.
- [x] Cache unsuccessful collection or use a bounded retry policy. Re-enable
  collection after reference changes or sufficient evictions; handle overwrite,
  erase, reset, resize, and alternate-screen transitions.
- [x] Verify reclaimed capacity becomes usable and existing cluster IDs remain
  correct after compaction.
- [x] Re-run the full-table reproduction and normal Unicode throughput checks;
  avoid timing-only assertions and heap allocations on steady hot paths.

Acceptance: table exhaustion has bounded amortized work and does not prevent
capacity recovery when clusters become unreferenced.

## 2. P2 — Explicit high image IDs are prematurely deleted

Location: `src/terminal/graphics.rs`, `auto_id` and `prune_dead_auto_ids`.

The pruning predicate treats every ID at or above 2^24 as automatically assigned.
Kitty permits explicit IDs across the full unsigned 32-bit range. Reproduction:
display image 1, transmit image 16777216 without placing it, then scroll at the
bottom of the screen. The explicit image exists before scrolling and is absent
afterward because the other placement triggers pruning. An executed harness
used `Grid::new(80, 24)` and fed Kitty commands through `Grid::feed_byte`, followed
by cursor positioning to row 24 and a newline. Observed output:

```text
explicit image before scrolling: true
explicit image after scrolling: false
```

This confirms parser/grid behavior; no GPU rendering assertion was made.

- [ ] Add that regression and cover explicit IDs at the boundary and u32::MAX.
- [ ] Track automatic assignment explicitly rather than inferring it from the
  numeric ID. Handle replacement of an automatically assigned ID by an explicit
  transmission and cleanup on deletion, eviction, and reset.
- [ ] Keep automatic image reclamation working for Sixel and Kitty images,
  including regular and Unicode virtual placements.

Acceptance: explicit transmit-only images survive scrolling until deletion or
normal quota eviction; unused automatically assigned images are still reclaimed.

## 3. P1 — Objective-C ABI mismatch on x86_64 macOS causes SIGSEGV (CWE-686, CWE-843)

Location: `src/platform/macos/objc.rs` (`msg_send!`), `src/platform/macos/window.rs` (`is_in_window_header`, `toggle_window_zoom`, `apply_window_config`).

`NSRect` is a 32-byte struct (4 `f64` fields). Under the Apple System V AMD64 ABI
on x86_64 macOS, any Objective-C method that returns a structure larger than
16 bytes must be dispatched using `objc_msgSend_stret` rather than `objc_msgSend`.
In `msg_send!`, transmuting to `objc_msgSend` causes the return buffer pointer
in `%rdi` to be misinterpreted as `self`. Dereferencing `isa` from caller stack
memory causes an immediate segmentation fault (`EXC_BAD_ACCESS` / `SIGSEGV`) on
Intel Macs or Rosetta 2 upon header double-click, window zoom, or vibrancy setup.
(On ARM64, structs up to 32 bytes are returned in vector registers `v0..v3`, so
ARM64 is unaffected).

- [ ] Declare `objc_msgSend_stret` in `src/platform/macos/objc.rs` for `x86_64`.
- [ ] Specialize `msg_send_stret!` or route calls returning structs > 16 bytes
  through `objc_msgSend_stret` when `target_arch = "x86_64"`.
- [ ] Add unit test verifying struct return signatures on macOS targets.

Acceptance: window header double-click, titlebar zoom, and frame queries execute
cleanly without ABI faults on both `x86_64` and `aarch64` macOS targets.

## 4. P1 — Sub-frame APNG decodes trigger wgpu buffer underflow panic (CWE-125, CWE-754)

Location: `src/terminal/graphics.rs` (`decode_png`, `kitty_frame`), `src/render/image_layer.rs` (`ImageLayer::upload`).

`decode_png` reads canvas dimensions `(w, h)` from `reader.info()`. When decoding
an APNG or chunked PNG with sub-frame bounds (`info.width < w` or `info.height < h`),
`info.buffer_size()` is strictly smaller than `w * h * 4`. `decode_png` returns
`Ok((w, h, rgba))` with `rgba.len() < w * h * 4`. When passed to `queue.write_texture`
in `ImageLayer::upload`, `wgpu` detects buffer underflow and panics with a validation
error (`copy of X bytes would overflow data buffer of size Y`). In `kitty_frame`,
indexing `pixels[((y * fw + x) * 4) as usize..][..4]` also panics with out-of-bounds
slice indexing.

- [ ] Add a regression test with an APNG containing sub-frames (`fcTL` smaller than canvas).
- [ ] In `decode_png`, blit sub-frames into a full `w * h * 4` buffer at `(x_offset, y_offset)`
  or reject mismatched frames with `EINVAL:bad PNG`.
- [ ] Enforce invariant: `decode_png` must only return `Ok` when `rgba.len() == (w * h * 4) as usize`.

Acceptance: APNGs and sub-frame images cannot panic `wgpu::write_texture` or `kitty_frame`.

## 5. P1 — Curl `--config -` parses leading `@` as arbitrary file inclusion (CWE-20, CWE-73)

Location: `src/ai/http.rs`, `once`.

In `curl` config files (`-K` / `--config -`), the `data-binary = "<payload>"` directive
unquotes the string. If the payload begins with `@`, `curl` treats the rest of
the string as a local file path, reading the file from disk and transmitting its
contents as the HTTP request body. Reproduced empirically with a local test HTTP
server: `data-binary = "@/etc/hosts"` transmitted all 243 bytes of `/etc/hosts`.

- [ ] Add a regression test verifying that payloads starting with `@` are sent literally.
- [ ] Replace `data-binary = ...` with `data-raw = ...` in `src/ai/http.rs`.
- [ ] Verify `data-raw` disables `curl`'s `@` file inclusion syntax.

Acceptance: AI prompt payloads starting with `@` are transmitted verbatim without
local file disclosure.

## 6. P2 — Standalone binary update copy follows existing symlinks (CWE-59, CWE-377)

Location: `src/update.rs`, line 940.

During standalone binary updates, `current_exe.with_extension("new")` produces a
predictable path `<binary>.new`. `fs::copy(downloaded_file, &temp_dest)` opens the
destination in write mode (`O_WRONLY | O_CREAT | O_TRUNC`) following symlinks.
If a symlink was planted at `<binary>.new`, `fs::copy` and subsequent `fs::set_permissions`
traverse the link and overwrite the victim target. Reproduced empirically with a Rust harness.

- [ ] Add regression test in `security_poc.rs` asserting symlinks at `<exe>.new` are
  unlinked and not followed.
- [ ] Unlink `temp_dest` prior to `fs::copy`, or create it using a secure temporary file
  descriptor opened with `O_CREAT | O_EXCL | O_NOFOLLOW`.

Acceptance: binary updates fail or unlink planted symlinks without modifying external targets.

## 7. P2 — Linux `alert_choice` drops "Cancel" button and force-opens browser

Location: `src/platform/linux/dialog.rs` (`alert_choice`), `src/app/user_event.rs`.

`user_event.rs` expects 3 choices for update notifications: `0` (Update Now),
`1` (View Release), `2` (Cancel). On Linux, `dialog.rs` passes only `--ok-label`
(button 0) and `--cancel-label` (button 1) to `zenity --question`, omitting button 2.
When the user closes the dialog, presses `Esc`, or clicks Cancel (or when `zenity`
is missing), `cmd.status().success()` is false, causing `alert_choice` to return `1`.
`user_event.rs` receives `1` and involuntarily launches the web browser via
`linux_open_command(&release.html_url)`.

- [ ] Support 3 buttons via `zenity --extra-button`.
- [ ] Map dismissal / non-zero exit code to index `2` (Cancel) or `usize::MAX`.
- [ ] Ensure non-Zenity headless environments do not launch a browser upon update check.

Acceptance: closing or cancelling an update prompt on Linux does not launch the browser.

## 8. P2 — Font missing horizontal line metrics panics terminal startup (CWE-754)

Location: `src/render/atlas/mod.rs` (`cell_size_pt`, `Atlas::new`), `src/render/atlas/fonts.rs` (`parse_font`).

`fontdue` returns `None` for `font.horizontal_line_metrics()` if the font lacks an
OpenType/TrueType `hhea` table. In `cell_size_pt` and `Atlas::new`, `.expect("font has no horizontal line metrics")`
is called on the primary font. A user-configured font lacking `hhea` panics the app
immediately during window creation or config reload.

- [ ] In `parse_font`, check `font.horizontal_line_metrics(32.0).is_some()` before
  accepting a font as the primary monospace font.
- [ ] Provide synthesized fallback line metrics when metrics are absent.

Acceptance: fonts lacking horizontal line metrics either fall back cleanly or synthesize
metrics without panicking.

## 9. P3 — Process-wide `libc::umask(0o177)` in daemon control socket listener (CWE-362)

Location: `src/platform/control_socket.rs`, `listen`.

Modifying `libc::umask(0o177)` changes the file creation mask for the entire process
across all threads during `UnixListener::bind`. Since the parent cache directory
is already restricted to `0o700` (`set_permissions`), the directory boundary
protects the socket.

- [ ] Remove process-wide `umask` mutation to avoid race conditions with concurrent threads.

Acceptance: control socket creation does not alter process-wide `umask`.
